# Security / UX audit for `new-quiz`

Дата: 2026-07-07

## Что исправлено патчем

### 1. CORS был слишком доверчивым
API отражал любой `Origin` в `Access-Control-Allow-Origin`. Это удобно при разработке, но плохо для админских и платных функций.

**Патч:** `corsHeaders()` заменяется на версию с whitelist через `ALLOWED_ORIGINS`.

### 2. Нельзя доверять Telegram ID из браузера
В коде есть режим `ALLOW_UNTRUSTED_ACCESS`. Если он включён, пользовательский ID может быть принят без Telegram-подписи.

**Патч:** небезопасный режим выключен по умолчанию. Включить можно только специальным явным значением, но лучше не включать вообще.

### 3. Admin key в URL
Админ-секрет через `?key=` может попасть в историю браузера, логи, Referer и скриншоты.

**Патч:** по умолчанию принимается только заголовок `X-Admin-Secret`.

### 4. `/api/health` раскрывал внутренние ключи
Ответ показывал служебные названия ключей KV/Blob и TTL.

**Патч:** health endpoint теперь возвращает минимум: `ok`, `service`, `time`.

### 5. Нет защитных HTTP headers
Для статического сайта стоит явно добавить заголовки от MIME-sniffing, лишних permissions, clickjacking и утечек referrer.

**Патч:** обновлён `netlify.toml` с security headers.

### 6. Меню было перегружено
Функции не удалены, но сгруппированы: обучение, тесты, результаты, доступ, настройки. На телефоне добавлена нижняя быстрая панель.

**Патч:** `public/secure-ui.css` + `public/secure-ui.js`.

## Что ещё важно сделать руками

1. Ротация секретов: если бот-токены или admin secret когда-либо попадали в GitHub, перевыпусти их.
2. Не держи настоящие токены в файлах репозитория. Только Netlify Environment variables.
3. Не включай `ALLOW_UNTRUSTED_ACCESS=1`.
4. Лучше сделать репозиторий private, если в нём есть платная логика и база вопросов.
5. Лимиты на клиенте легко обходятся. Всё, что связано с подпиской, лимитами и баном, должно проверяться backend-ом.
